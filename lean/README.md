# Thin Ice in Lean 4

Machine-checked statements about Thin Ice, in core Lean 4 (no Mathlib).

```
cd lean
lake build
```

Toolchain: `leanprover/lean4:v4.35.0` (pinned in `lean-toolchain`, installed by elan). A clean
build takes about 1 minute on a desktop PC (53 s measured, files checked in parallel; the
slowest file is P11 at about 50 s). Every theorem below is checked in that build.

## What is in here

| File | What it holds |
|---|---|
| `ThinIce/Rules.lean` | The rules, written by hand from `thinice/board.py`: squares, the 8 directions, sliding moves, the 3-in-a-row lines. The specification `ForcedWin`, the checker `check`, and the proof `check_sound`. |
| `ThinIce/Puzzles.lean` | The 12 scored puzzles (seed `"1"`), with the legal Blue moves Python lists for each. Generated by `tools/lean_export.py`. |
| `ThinIce/Hints/Pxx.lean` | Untrusted hints: for each Blue-to-move node of Blue's strategy, the move to play. Generated by `tools/lean_export.py` from `thinice/search.py`. |
| `ThinIce/Validate.lean` | The Lean rules agree with `board.py` on all 12 start positions. |
| `ThinIce/Mistake.lean` | The showcased mistake in P07. |
| `ThinIce/Wins/Pxx.lean` | One forced-win theorem per puzzle. |

## The definitions

- A position is two 42-bit masks, Blue's stones and Red's stones; square = row * 7 + column,
  a1 = 0, as in `board.py`.
- `moves mine occ`: every (from, to) where a stone of `mine` slides in one of 8 directions until the
  next cell is off the board or occupied, and moves at least one cell.
- `hasLine m`: the stones `m` include three adjacent cells in a row, column or diagonal.
- `ForcedWin n me opp` (an inductive definition, the specification): the side to move can force
  three in a row within `n` of its own moves. Either some legal move makes a line at once, or some
  legal move leaves the opponent with only replies that make no opponent line and after each of
  which `ForcedWin (n - 1)` holds. An opponent with no legal move has no replies, so it loses.

## The theorems

- `check_sound`: for any hint table, if `check hint n me opp` returns `true` then
  `ForcedWin n me opp`. Proved by induction, no `native_decide`. This is why the hints need not be
  trusted: the checker re-verifies every move and every reply against the rules, and the hints only
  say which Blue move to try.
- `rules_match_python`: for all 12 start positions, the Lean list of legal Blue moves is the same set,
  with the same count, as `board.moves`, and no side starts with a line.
- `P07.blue_move_count`: P07 has 25 legal Blue moves.
- P07, Blue to move (Blue on 2, 7, 30, 32; Red on 6, 16, 17, 25):
  - `P07.c1g5_legal`, `P07.c1g5_no_line`: c1-g5 (2 to 34) is legal and does not win at once.
  - `P07.c1g5_loses`: after c1-g5, Red has a forced win within 2 Red moves.
  - `P07.red_winning_moves`: Red's moves that keep that win are exactly c3-e1 and d3-f1. This one is
    an exhaustive search with no hints, and it matches the Python search.
- `Pxx.blue_wins` for P01 to P12: Blue, to move in the start position, has a forced win within N
  Blue moves:

| Puzzle | Blue | Red | N |
|---|---|---|---|
| P01 | 4, 6, 20, 40 | 11, 17, 35, 37 | 1 |
| P02 | 19, 21, 22, 27 | 0, 14, 18, 31 | 1 |
| P03 | 3, 18, 27, 39 | 7, 13, 14, 26 | 2 |
| P04 | 6, 28, 32, 41 | 0, 3, 11, 22 | 2 |
| P05 | 0, 19, 34, 40 | 3, 7, 30, 33 | 3 |
| P06 | 5, 6, 32, 35 | 18, 20, 23, 37 | 3 |
| P07 | 2, 7, 30, 32 | 6, 16, 17, 25 | 4 |
| P08 | 6, 31, 32, 38 | 4, 11, 17, 40 | 4 |
| P09 | 0, 2, 20, 25 | 3, 6, 12, 17 | 5 |
| P10 | 4, 21, 22, 41 | 14, 24, 29, 31 | 5 |
| P11 | 5, 33, 36, 39 | 17, 22, 27, 38 | 6 |
| P12 | 12, 17, 24, 30 | 14, 18, 19, 38 | 6 |

All 12 build. P01 to P11 are checked by the kernel (`decide +kernel`); P12 is checked with
`native_decide`, because the kernel took more than 5 minutes on it.

## What is trusted

- The Lean kernel (with its built-in fast arithmetic on natural numbers). Everything except
  `P12.blue_wins` is checked by the kernel alone: `#print axioms` shows only `propext` and
  `Quot.sound`.
- For `P12.blue_wins` only: `native_decide`, and so the Lean compiler and its runtime, because the
  check runs as compiled code instead of being reduced by the kernel.
- That `Rules.lean` says the same thing as `board.py`. It is a hand copy. `rules_match_python` and
  the P07 result (the same two Red moves as the Python search) are evidence for this, not a proof.
- The 12 positions in `Puzzles.lean` are the ones the game server picks; they were written out by
  `tools/lean_export.py` using `thinice/session.py`.

Not trusted: the hints. They come from the Python search, and a wrong hint can only make a
theorem fail to build.

## What is NOT proven

- That N is the fewest moves (that Blue has no faster win).
- That a given Blue move is the only one that keeps the win, or which moves lose, except for the
  one P07 line above.
- Anything about draws, or about the game as a whole (the solved game, the solver's tables).
- That the Rust solver or the puzzle packs are correct beyond these 12 positions.

## Regenerating

```
python tools/lean_export.py        # writes ThinIce/Puzzles.lean and ThinIce/Hints/*.lean
```

The win-in-6 strategies take about a minute and a half of Python search.
