Thin Ice: how far ahead can a model plan?

We invented a board game, solved every position, and asked AI models to find forced wins one to six moves away, with no code and no search tools. The planning has to happen in their own reasoning, and every move they make gets an exact verdict.

Thin Ice. Every mistake, proven.

01The game

A board game we invented, then solved completely

Thin Ice is played on a 7 by 6 board. Blue and Red have four stones each. A stone slides in a straight line until something stops it, and three in a row wins.

The board is small enough to solve outright: all 16.5 billion positions have a known result. So for any move a model makes, we know exactly whether it keeps a forced win or throws it away.

The rules in motion. The rule being shown is highlighted.

Run Thin Ice on your model

You need Harbor (uv tool install harbor) and Docker (or Modal), and for step 3 your provider’s API key.

  1. 01Get the code

    git clone https://github.com/hectoragofi/thin-ice && cd thin-ice

  2. 02Check the setup: perfect play, search and baselines, no key needed

    python scripts/evaluate.py

  3. 03Run your model: 3 runs and one table at the end

    python scripts/evaluate.py --model google/gemini-4-carbon

One run straight through Harbor

harbor run -p task -a opencode -m <provider>/<model>

A fresh draw of 12 puzzles from the pool

THINICE_SEED=7 harbor run -p task -a opencode -m <provider>/<model>

More or less thinking effort

harbor run -p task -a opencode -m <provider>/<model> --effort high

The deeper set: wins 7 to 9 moves away

python experiments/deep/build_deep.py && harbor run -p experiments/deep/task -a opencode -m <provider>/<model>

Add --env modal to run on Modal instead of Docker. Everything else is in the README on GitHub.

    The task in full

    Proven in Lean

    lean/ThinIce/Mistake.lean

-- After c1-g5, Red (to move) forces three in a row within 2 Red moves.
theorem P07.c1g5_loses : ForcedWin 2 P07.red P07.afterC1G5 :=
  check_sound noHint 2 _ _ (by decide +kernel)

-- Red's winning first moves are exactly c3-e1 and d3-f1.
theorem P07.red_winning_moves :
  winningMoves 1 P07.red P07.afterC1G5 = [(16, 4), (17, 5)] := by decide +kernel

    11 of the 12 are checked by Lean’s kernel alone; P12 also trusts the compiler. Not proven: that a win is the fastest, that a move is the only one that holds (except P07), or the solved game as a whole.

    Attacks on our own score

    The score sheet is HMAC-signed by the game server. The verifier runs in its own container, which the agent never touches.
